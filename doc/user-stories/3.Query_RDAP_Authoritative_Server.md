### Description

As an SEO auditor,
I want to query the RDAP Authoritative Server for a given domain name
So that I can verify the domain name is registered and store some basic registration data.

### Acceptance Criteria

1. The service will call the
   external RDAP Authoritative Server
   for a given domain name
   that is known to exist.
1. If the domain name is not registered,
   the system will return an error message.
1. If an error occurs while retrieving the data,
   the system will return an error message.
1. Functional tests can use andexor.net
   as a good example of a domain name
   that is registered.
1. Functional tests can use andexor-nxdomain.net
   as a bad example since it does not exist.
1. Functional tests should also use
   other existing domains
   with a TLD that is not .com, .net, or .org.

### Technical Details

#### General

1. This will be implemented as
   a REST web service.
1. Although this can be called independently,
   it will typically be called by the
   AGS RDAP Agent.
1. The service will be written in Python.
1. It will use the whodap library
   to make requests to the
   External RDAP Bootstrap Server.
1. Configure whodap to use the AsyncClient
   from HTTPX to make async requests.
1. Use aio_lookup_domain to perform
   the lookup asynchronously.
1. If you get a 429 response code,
   check the Retry-After response header
   to know how long to wait,
   then make another request after that time
   has passed.
   If there is no Retry-After response header,
   wait 1 second and try again.
1. Wrap the call to aio_lookup_domain
   in a try/except block to catch exceptions.
1. Add `strict = True` in a comment
   just before the try/except block
   so that the RDAP response
   will be validated and raise an exception
   if there is a formatting issue.
1. The service will emit telemetry data
   as logs, metrics, and traces.
1. All requests, responses,
   observations, and decisions
   will be saved in a database
   for analysis and reporting.

#### Request

Parameters:

- url
  - type: string
  - sub-type: URL
  - max length: 255 characters
  - details:

The URL is generally the one obtained by
the the AGS RDAP Bootstrap Service.

Feel free to use a variety of invalid URL formats
for negative testing in unit tests and functional tests.

Validate the URL before using it.
If validation fails, abort the mission
and return an error response.

#### Response

Return the entire JSON response
from the RDAP Authoritative Server.

#### Documentation

- The code shall have proper documentation
  for all classes and methods,
  including the name, type, purpose, and constraints of all parameters,
  return values, and exceptions. It should follow a recognized
  standard format and it should be formatted in a compact way (no blank lines).

  This documentation shall be hosted with the web APIs so that it can be browsed live
  while the service is running.

  as `.png` images during the build process.
